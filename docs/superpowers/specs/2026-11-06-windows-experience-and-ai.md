# Windows 书写体验与 AI 讨论面板

日期：2026-11-06。状态：原三项详细设计已获用户认可；第 10 节为用户补充需求的设计展开，随实施计划评审。本文不是已实现功能或实机验收记录。

## 1. 已确认目标与本轮默认选择

用户已确认：优化 Windows 打开作品菜单、外观弹窗时正文消失的体验；优化 Windows 退出等待；在“灵感”右侧增加 AI 页签，自配 API Key，支持 DeepSeek、Kimi、GLM、Qwen、OpenAI。AI 定位为思路整理、内容评价和总结。

本设计采用以下默认选择，作为本次评审内容：

- 桌面客户端直接请求用户选择的模型服务；沿用现有主题、可调宽度的右栏和原生正文编辑器。
- 一台设备保存各厂商的连接配置；API Key 使用 Windows 凭据管理器、macOS 钥匙串。
- 每部作品在本机保留一份当前对话；“新对话”清空当前对话前确认。首版不增加多会话管理、云同步或聊天导出。
- 默认仅发送用户输入及当前对话历史。正文通过一次性的“选中文字 / 当前章节”附件主动加入。
- 回复提供选择、复制；不提供自动应用到正文、续写、改写、润色入口。本轮不增加全书索引、联网搜索、工具调用或文件上传。

成功条件：菜单打开后正文仍可阅读；正常退出只等待必要的本地工作；用户能完成配置、对话、附加内容、取消和重试，稿件保持原有保存与撤销行为。

## 2. 当前代码证据

### 2.1 Windows 正文消失

`lib/features/editor/novel_editor.dart` 在 `overlayOpen` 或当前路由被覆盖时发送 `visible: false`；`windows/runner/native_novel_editor.cpp` 收到后调用 `ShowWindow(..., SW_HIDE)`。Flutter 侧对应位置仅为占位容器，故隐藏原生窗口后没有正文可显示。

这是当前层叠方案的直接结果：原生 HWND 位于 Flutter 绘制内容之上，简单保持显示会遮挡菜单、弹窗及遮罩。仅设置只读不能解决遮挡问题。

### 2.2 Windows 退出等待

`lib/main.dart` 等待 `prepareToQuit()` 后销毁窗口；当前 `prepareToQuit()` 复用更新准备流程。`flushAll()` 包含同步原生状态、正文保存、笔记保存、字数计算、`_snapshotAll()`、记录阅读位置。

`_snapshotAll()` 对当前正文和全部笔记逐项调用 `HistoryStore.capture()`。每次 capture 先列举并读取该记录的全部历史 JSON，再判断内容是否变化；新增历史时还会再次列举。历史最多保留 100 份，未变化内容也会发生扫描。这是高概率耗时点，尚未通过 Windows 分段计时确认其占比。

此外，窗口销毁后未显式调用 `_instanceLease.close()`；需要分别检查“窗口关闭耗时”和“进程完全退出耗时”，不能假设两者相同。

### 2.3 AI 接入位置

`NotesPanel` 当前由 `NoteKind` 驱动“大纲 / 角色 / 灵感”三个页签；工作台的 `panel` 类型也为 `NoteKind?`。AI 是独立工具，应引入面板选择类型，映射现有三类笔记并增加 AI，避免把 AI 写入作品笔记格式。

现有 `PreferencesStore` 使用明文 JSON，适合保存地址和模型名，不适合存 API Key。macOS 已包含客户端网络权限，仍需在发布构建验证。

## 3. 方案选择

| 方向 | 备选方案 | 取舍与选择 |
| --- | --- | --- |
| 正文层叠 | 保留原生控件并按弹窗区域裁剪；隐藏时显示原生视口快照；统一更换正文编辑器 | 采用快照：局部修改即可覆盖菜单、遮罩、弹窗；裁剪需要维护所有浮层几何，更换编辑器影响输入法与排版 |

| AI | 多套厂商 SDK；共同协议加少量厂商参数；自建中转服务 | 采用共同协议，客户端直连；无须运行额外服务，也不引入多套 SDK |

## 4. Windows 浮层期间的正文显示

### 4.1 显示与交互状态

正文分成“正常编辑、快照准备、快照展示”三个状态，编辑器实例全程保留。作品菜单、外观、AI 设置及其他会覆盖编辑区的路由统一接入；单纯切换右栏页签不触发快照。

1. 浮层请求打开时，在原生控件仍可见的状态下获取当前视口画面，并暂时阻止正文输入；记录文档 ID、代次、物理尺寸和缩放比例。
2. Flutter 将画面放在原正文占位区域，使用原视口尺寸和位置，不重新排版文字。快照首帧就绪后隐藏 HWND，允许浮层显示。
3. 展示期间正文不可编辑、不可滚动；点击菜单外部按浮层规则关闭，不穿透成为正文输入。快照不显示闪烁光标。
4. 最后一个浮层关闭后，先恢复 HWND 位置、可见性和重绘，再释放快照；仅在打开前焦点属于正文时恢复正文焦点。

多个浮层同时存在时，只在从零到一个、从一个到零时转换。异步回包携带代次；过期画面不覆盖当前章节，销毁组件后释放图像资源。

### 4.2 捕获与更新

原生桥新增获取视口画面的能力，使用内存位图请求 RichEdit 绘制客户区，经方法通道传回像素数据。优先验证 `WM_PRINTCLIENT` 对当前 RichEdit 的实际支持；微软文档描述了该消息的绘制契约，但不能据此声称本控件已通过验证。[微软 WM_PRINTCLIENT 文档](https://learn.microsoft.com/en-us/windows/win32/gdi/wm-printclient)

外观设置导致纸色、文字色或排版变化时，在原生控件应用配置后更新快照；窗口尺寸或 DPI 变化也更新。请求合并为最多一个在途任务，仅渲染最新状态，避免主题动画每帧捕获。更新时保留上一份有效画面，不出现空白。

若原生捕获验证不能稳定覆盖滚动、长段落和 DPI，本项不得按已完成交付；保留现有可操作浮层路径并报告验证结果，再评估替代捕获方式。不得以持续显示遮挡弹窗的 HWND 作为降级方案。

### 4.3 验收

- Windows 100%、125%、150%、200% 缩放；深浅主题、有背景图、长章节、中间滚动位置。
- 连续打开关闭作品菜单与外观弹窗，正文保持可见，弹窗可点击，关闭后可继续输入。
- 变更字号、行距、纸色后快照与恢复后的正文一致；选区、滚动、撤销栈不重置。
- 中文输入法组合期间打开弹窗，按原有焦点规则提交或结束组合，不丢字、不重复字。
- 快速切章节、连续浮层、窗口缩放时，旧图像不闪回、不泄漏资源。

## 5. Windows 退出优化

### 5.1 先测量，再限定修改范围

在调试或专用探测入口用单调时钟记录：原生锁与输入法提交、等待作品操作、正文落盘、笔记落盘、历史捕获、位置与配置落盘、资源释放、窗口销毁。只记录阶段和耗时，不记录正文、路径或密钥。

用同一 Windows 机器、同一构建做修改前后比较：无作品；未编辑作品；刚输入后立即退出；100 条笔记且每条 100 份历史；10 万字当前章节。每组至少测 10 次并记录中位数和最慢值。检查窗口是否消失，以及进程是否真正结束。

### 5.2 保存与历史

- 保留原生输入锁、组合提交、已有作品操作排空、正文/笔记可靠保存、位置配置保存；重复退出请求共用同一个准备任务。
- `HistoryStore` 在本次进程内记住已成功捕获的最新哈希；首次访问通过现有历史扫描建立状态，之后相同内容直接返回。
- 同一记录的捕获按顺序执行；仅成功落盘后更新缓存。读取历史列表、恢复或删除历史时使相应缓存失效。历史文件归应用管理；外部修改造成读取或写入失败时清空缓存并重新扫描，不将失败当成已捕获。
- 作品加载时完成现有初始历史状态的建立；笔记保存成功后记录待捕获的版本，后续保存/退出只处理这些变更。与启动时历史捕获共用队列，避免退出竞态。原有版本和最新快照均须可恢复。
- 字数结果仅在对应正文版本相同且计算已完成时复用；不复用旧章节或旧版本结果。
- 不通过删掉可靠写入、跳过保存、无限后台保存或强杀进程提速。历史失败继续遵循现有“稿件已保存、历史未更新”提示语义。

### 5.3 退出资源与失败恢复

稿件保存成功后，停止 AI 请求、等待当前本地对话保存任务、关闭 AI 网络客户端，再释放单实例服务器与文件锁，最后销毁窗口。正在生成的回复以“已停止”保存已收到部分，不等待模型完成。AI 对话保存失败允许用户重试或明确选择放弃该次对话保存，不能丢失稿件错误提示。

若正文或笔记保存失败，保留窗口、恢复编辑与焦点并提示原因；释放单实例锁必须在决定退出后进行。升级安装路径复用可靠保存部分，仍满足现有更新安全测试。

验收目标：未变化作品的重复退出不再扫描全部历史、不新增历史文件；变更记录只产生必要快照；正常本地磁盘上，保存准备的中位数目标低于 500ms，窗口和进程退出目标低于 1s。这些是测量目标，不是对任意磁盘或杀毒环境的时限承诺；未达到时列出实测瓶颈。

## 6. AI 面板与主要流程

### 6.1 布局

右栏页签顺序为“大纲 / 角色 / 灵感 / AI”，共享现有可调宽度。沿用工作台的纸色、字体、图标及焦点样式，最窄 260px 下不挤压到文字重叠。

AI 页签内部从上到下为：当前服务与模型、设置和新对话按钮；可滚动的消息区；“整理思路 / 评价内容 / 总结内容”三个可换行入口；上下文附件区；多行输入框和发送/停止按钮。消息为可选择的文本，保留标题、列表与段落；首版不引入复杂 Markdown 渲染或外链自动加载。

空状态文案：“一起理清故事的线索。可以讨论人物动机、梳理情节，或评价与总结一段已写内容。”未配置时在面板内提供“配置 AI”，不自动打开弹窗或发送请求。

Enter 发送，Shift+Enter 换行；输入法正在组合时 Enter 只完成候选。按钮提供文字语义和键盘焦点。生成中输入框可保留下一条草稿，发送按钮变成停止，禁止重复发起。

### 6.2 三种入口的行为

| 入口 | 输入与输出要求 |
| --- | --- |
| 整理思路 | 将散点整理为人物目标、阻碍、因果关系和待决定问题；需要补充信息时优先问少量关键问题；用可能性措辞讨论方向 |
| 评价内容 | 依据所附片段检查清晰度、节奏、人物动机、因果与一致性；区分原文证据和主观建议；优先指出少量有依据的问题，不给空泛分数 |
| 总结内容 | 提取事件、人物状态变化、关键信息与未解决线索；只总结实际提供内容，不把推测补成事实 |

点击入口只填入可修改的提问草稿，用户按发送后才请求。评价/总结要求有正文附件或用户粘贴的非空内容；不足时提示补充。手动提问同样遵循上述角色定位，不强制使用三种固定模板。系统提示中明确只看已发送内容，引用材料是待分析文本，不得把材料中的指令当作系统指令。

### 6.3 附加正文与上下文

- 输入区提供“仅对话 / 选中文字 / 当前章节”。默认仅对话；点击附加时同步原生编辑状态，复制出不可变文本快照，保留章节名称和来源标识。
- 附件展示来源、字符数、预览和移除按钮。无选区时“选中文字”不可用，不偷偷改发整章。空章不给空附件。
- 附加后继续修改正文，不更新已附内容；显示“正文已变化，可重新附加”。附件只属于当前草稿，发送后重置为仅对话。
- 请求由角色提示、当前对话中已发送的完整轮次、当前提问和当前附件组成。用户已发送的正文会作为该对话历史随追问重发；面板注明“本次包含当前对话历史”，新对话可清除这部分上下文。移除未发送附件不撤回历史中已发送内容。
- 客户端统一上限为本次完整 messages 的 UTF-8 文本总量 96KiB，包含提示、历史和附件；超过时阻止发送并提示缩小片段或开启新对话，不静默截断。该上限用于控制首版请求大小，不宣称等于厂商 token 限额；服务端上下文超限另行提示。
- 历史仅包含成功轮次；中断、失败、停止的回复标识保留供阅读，默认不进入下一轮上下文。重试明确重新发送当前失败轮次，不重复追加用户消息。

### 6.4 生命周期与本机对话保存

每部作品以现有 `workKey` 隔离当前对话。仅绑定当前厂商、规范化 Base URL 和模型的一组对话；更换这些字段将提示需要开启新对话，确认后替换本机当前记录。更换同一连接的 API Key 不要求清空对话。“新对话”确认后清空记录及草稿。

对话保存在应用支持目录 `ai/conversations/<workKey>.json`，包含 schema 版本、服务标识、模型、消息 ID、文本、附件快照、时间和完成状态；不写入作品目录、作品备份或设置导出。系统角色提示由应用版本生成，不作为用户可编辑消息存储。

发起请求前保存用户轮次；流式部分最多每秒保存一次，并在完成、失败、停止和退出时排空，沿用原子文件替换。保存失败在面板内显示并可重试。启动时把遗留“生成中”改为“已中断”。消息正文在本机普通文件中保存，与系统凭据中的密钥分开。

切换作品取消当前请求、保存已收到内容并切换对话；切换右栏页签仅隐藏面板，请求继续。每个回包校验作品键、对话代次和请求 ID，过期回包不得污染新作品或新对话。打开作品菜单和外观设置不取消请求。

## 7. 模型配置、协议与网络行为

### 7.1 配置界面

字段为服务商、Base URL、模型 ID、遮蔽的 API Key；模型可手动输入，避免模型更新必须发布客户端。每个厂商保留一份配置，自定义服务保留一份配置。首次必须由用户选择服务商，不替用户默认选择付费服务。

提供保存、测试连接和删除密钥。测试使用当前填写值发送固定的极短测试消息，不附加稿件、对话和作品名；按钮旁说明会产生一次模型请求。保存配置本身不联网，测试失败不清除现有密钥或配置。

非密钥设置保存于设备配置；凭据以服务商和规范化地址派生的稳定标识存入系统。变更地址必须重新填写密钥，避免旧密钥随地址变更自动发给另一服务。模型变化可继续使用同一凭据。保存凭据失败时不退回明文保存，提示用户重试。

### 7.2 首版协议边界

采用 HTTPS Chat Completions：JSON 请求、Bearer 鉴权、SSE 文本增量回复；共用传输、事件解析和错误映射。基本请求仅发送 model、messages、stream 及所选厂商明确需要的参数；不统一硬塞 temperature、tools、response_format 等可选字段。输出长度字段通过厂商配置适配，默认目标 2048 输出 token；实际可用模型必须支持文本 Chat Completions。

OpenAI 的流式回复采用 `choices[].delta`，内容字段可为空，usage 事件可能没有 choices；消费者必须处理空内容和独立结束事件。[OpenAI 官方流式事件文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)

| 服务 | Base URL 初始化方式 | 官方参考 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com`，直接拼接 `/chat/completions` | [首次调用](https://api-docs.deepseek.com/) |
| Kimi | `https://api.moonshot.cn/v1` | [Chat Completions API](https://platform.kimi.com/docs/api/chat) |
| GLM | `https://open.bigmodel.cn/api/paas/v4` | [OpenAI 兼容](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction) |
| Qwen | 按控制台地域/业务空间填写，提示示例 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`；占位符未替换禁止发送 | [兼容说明](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope) |
| OpenAI | `https://api.openai.com/v1` | [官方 Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) |
| 自定义 | 用户填写兼容服务的 HTTPS Base URL | 仅承诺本节共同协议 |

这些是 2026-11-06 核对的接口信息；地址可修改，模型 ID 由用户填写。支持厂商表示实现其文本协议并通过对应验证，不表示任意模型、订阅或账号都有权限。Qwen 的地域和密钥应匹配，设置中以帮助文字说明这一点。

Base URL 限 HTTPS，拒绝含账号密码、查询串、片段和未替换占位符的地址；规范化末尾斜线后追加 `/chat/completions`，不重复追加 `/v1`。配置页面显示实际请求地址。禁止自动跟随重定向携带凭据，不自动切厂商、不忽略 TLS 错误。网络可达性沿用系统环境，首版不另加代理配置。

### 7.3 请求状态和错误

状态为未配置、空闲、连接中、接收中、完成、已停止、失败。连接/首个 SSE 事件等待上限 60 秒，后续事件空闲上限 60 秒，总请求上限 5 分钟；计时以实际收到事件重置，而非只看可见文本。持续推理但无正文时显示“模型处理中”，不把推理过程当作回答正文持久化。

SSE 解析跨网络分片处理 UTF-8、CRLF、多行 data、注释心跳、`[DONE]` 与 finish_reason；容许非文本扩展字段，对不支持的工具返回给出明确错误。服务端非流式 JSON 成功响应可以显示完整文本；流异常结束而无完成标记时保留部分并标为中断。

401/403 提示检查密钥或权限；404 提示地址/模型；429 提示限流或配额；上下文超限提示缩小内容；连接、TLS、超时与服务端错误分别显示可理解的提示。保留草稿和部分回复，提供手动重试，不自动重试产生重复费用。错误只显示经过清理的摘要，不展示原始请求体、授权头或可能回显密钥的响应。

## 8. 代码边界与变更范围

- `NovelEditor` 和 Windows 原生编辑器桥负责快照与可见性交接；复用原编辑会话，不增加第二个可编辑副本。
- `WorkbenchController`、`HistoryStore`、`NotesController`、退出监听负责计时、变更记录、保存排空和资源释放；保存失败与更新锁行为保持可测试。
- 引入独立的工作台面板选择类型；`NoteKind` 和已存在的作品 JSON 无需迁移。笔记页签与 AI 页签共用页签头，内容组件分别负责各自界面。
- `lib/features/ai/` 包含配置/消息模型、单一兼容 API 客户端、AI 控制器和面板。配置与对话的本地读写放独立 store；系统凭据通过小型平台接口隔离，可注入测试替身。
- 平台实现可复用现有方法通道设施，Windows 接凭据管理器，macOS 接钥匙串；不为了调用 HTTP 引入各厂商 SDK。首版不新增服务端。
- 不改官网、发布下载页、现有未提交的用户文件；不升级无关依赖，不在本轮增加其他写作工具。

## 10. 补充：iCloud 等共享目录的按需读取与加载反馈

### 10.1 新增目标与证据

用户补充：共享文件夹中的大作品加载和更新必须按需进行，并提供明确提示。此要求适用于所有目录，不依赖识别 iCloud 路径，也不假设文件在本地。应用不实现云同步协议，文件下载和同步仍由系统管理。

当前 `WorkRepository.open()` 经 `reload()` 逐项读取所有章节 JSON 和全部笔记正文；`_openWork()` 启动 `_indexWords()`，后台遍历全部章节 TXT；`checkExternal()` 对未统计章节再次读取正文。即使首次显示正文很快，后台统计仍可能触发整部作品的远端文件读取。

### 10.2 读取顺序和兼容性

- 首屏只等待作品清单及必要的未完成操作恢复；立即显示卷和章节 ID 对应的目录占位。先读取上次章节的信息与正文，无上次章节时按目录顺序寻找首个可用、未删除的章节，不先扫描全书。
- 章节信息按当前可见目录窗口加载，每批最多 32 条，离屏预取最多一批；元信息读取最多 4 个并发。正文只读取当前请求章节，取消后的已发出文件读取可能继续由系统完成，但结果不得安装到当前会话，不继续派生读取。
- 元信息未读取时显示“章节信息待加载”，不能构造标题为空的可写 `ChapterRecord`。当前章节最多保留一个正文会话；其他已读章节仅保留标题和字数等轻量信息，不缓存全书正文。
- 笔记未改变文件格式，kind、标题、正文仍在同一 JSON。首次可见的资料页签每批检查最多 16 个文件，以显式“继续加载资料”或滚动到底触发下一批；显示“已检查 N / M 份资料”。仅展示当前 kind 的已解析条目，尚未检查完时不宣称该类别为空。大纲父子引用未加载时标为“上级资料待加载”，编辑父子关系前加载并验证所需祖先链；不把未加载父项视为已删除。
- 默认打开右栏只会读取第一批资料，不自动为了找到某类别扫完全部笔记。读取到的资料留在当前作品的缓存中，切换页签复用已读记录，外部变更只失效对应条目。
- 现有作品格式版本仍为 1，不新增必须的共享索引文件，不要求原作品迁移。底层 eager 打开模式保留给原有工具/测试及明确的全量操作；正式工作台显式使用 lazy 模式。
- 全书字数不再驱动 TXT 读取。显示“已加载章节 X 字 · 全书未统计”，未知不是零；已有计数如因外部事件失效则标为待更新。首版不增加“统计全书”后台功能。

### 10.3 外部更新与写入安全

目录监听按相对路径合并事件。清单变化只更新目录结构；章节元信息变化只失效/更新该信息；非当前 TXT 变化只失效字数和版本提示，不读取正文；当前 TXT 更新才按需读取并比较。聚焦时检查清单与已加载条目的文件状态，不递归读取全部正文或笔记。

文件修改时间/大小只作跳过读取的优化，不能代替保存时的内容哈希冲突检查。监听丢失时提供“刷新目录”操作；它重新枚举文件名与清单并失效缓存，只重读可见条目和当前正文。刷新失败保留最后成功状态。

任何异步结果携带作品/章节/刷新代次。只允许最新请求安装结果；旧章节的保存任务须排空后再替换编辑会话。等待新章节时保留当前正文和草稿，加载提示明确写出目标章节；切换成功才更新标题与活动章节。最新请求失败时保留旧章可继续编辑，不能出现新标题配旧正文的可写状态。

未加载记录不可写入；缺失文件、未完成下载、无权限、离线与损坏均不替换成空稿。共享目录保存仍使用现有原子替换、版本冲突和操作日志。删除/恢复/彻底删除、父子关系修改、全书导出与备份需要的额外记录由用户操作显式触发，显示阶段进度并校验完整性；全书导出不漏掉未加载章节，彻底删除章节前必须加载并检查关联笔记。

未完成操作日志恢复可能需要读取日志涉及的文件，是加载首屏的必要例外。显示“正在恢复未完成操作”，失败时不得绕过恢复继续写入相关记录。冲突副本扫描只枚举候选与标识，用户比较时读取具体内容；不能借冲突扫描读遍全作品。

### 10.4 状态与等待反馈

开始读取即发布状态，在下一帧显示“正在读取作品目录 / 正在加载章节 / 正在读取资料 / 正在检查外部更新”；有可数单位才显示 N / M，不伪造下载百分比。等待超过 1 秒追加“文件读取较慢，云盘可能需要下载，请保持联网或稍后重试”。这只是等待提示，不断言检测到 iCloud 下载。

提供“返回作品库 / 取消本次加载 / 重试”中符合当前状态的操作。取消使当前请求失效并移除待调度读取，不承诺取消系统已开始的文件下载；新加载不等待旧批次整体完成，但元信息请求仍受并发上限约束，旧的在途读取占满名额时显示等待状态。当前章节正文请求独立于元信息队列。取消不能中断正在提交的写操作，保存失败仍保留稿件。

作品切换与目录加载、章节加载、外部刷新分别维护状态，不把全局 `busy` 用作覆盖整屏的万能加载锁。外部刷新只在状态区提示，已有正文可读；如需替换当前正文，先检查输入法、脏稿与保存状态，冲突时保留本机内容并提示。

### 10.5 验收与对原计划的修订

测试用可控制延迟和读取记录的存储替身验证：1000 个章节时首屏不读全部 TXT/JSON；可见目录批次和并发有界；笔记每批最多 16 份；未知字数显示正确；非当前章节变更不读 TXT；当前脏稿不被刷新覆盖；离线/取消/重复刷新/快速切章不写空稿、不串章；完整导出仍覆盖所有章节。慢读期间首帧有阶段提示，超过 1 秒出现等待说明。

macOS/iCloud 与 Windows 共享目录实机使用脱敏样例，分别验证本地已缓存、云端占位文件、断网和恢复联网。记录首屏时间、当前章节就绪时间及实际请求文件数；系统自动同步行为与应用主动读取数分开报告，不声称模拟延迟等同云盘验收。

修订实施顺序为：按需加载与进度 → Windows 退出与历史 → 正文浮层快照 → AI。第 5 节的历史初始化只能覆盖已加载记录，不得为了预热历史缓存读取全部云端内容；第 6 节 AI 的选区/当前章只允许取已就绪的编辑会话，不能触发全书读取。整体设计仍以原子保存和冲突保护为前提。
